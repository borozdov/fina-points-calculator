# Подвал: авторство и точка выхода

Строка авторства слева, кнопка-ссылка справа. Правится в [index.html](index.html),
блок `<footer class="footer">`.

## Ступени

Лейбл собран из кусков, которые CSS убирает по мере сужения экрана. Порядок жертв:
«СДЕЛАЛ» → полное звание → имя → фамилия. **Звание уходит последним и никогда
полностью** — ниже всех ступеней остаётся «МС».

| Ширина экрана | Лейбл                                    | Что скрыто                   |
| ------------- | ---------------------------------------- | ---------------------------- |
| ≥ 480px       | `СДЕЛАЛ NIKITA BOROZDOV · МАСТЕР СПОРТА` | —                            |
| 410–479px     | `NIKITA BOROZDOV · МАСТЕР СПОРТА`        | `.author-prefix`             |
| 320–409px     | `NIKITA BOROZDOV · МС`                   | `.author-rank`               |
| 280–319px     | `BOROZDOV · МС`                          | `.author-first`              |
| < 280px       | `МС`                                     | `.author-name`, `.author-sep`|

Замеренная потребность вариантов: 454 / 399 / 316 / 272 / 193px ширины экрана. Пороги
стоят выше замеров с запасом ~10px — кроме 320px, где запас 4px оставлен намеренно, чтобы
самый узкий реальный телефон сохранил полное имя.

Куски: `.author-prefix` (СДЕЛАЛ), `.author-name` (`<b>`, внутри — `.author-first` с именем),
`.author-sep` (·), `.author-rank` (полное звание), `.author-rank-short` (сокращённое).
Скрытые `display: none` куски выпадают и из дерева доступности — скринридер читает ровно
то, что видно.

`.author` — флексбокс, поэтому пробелы между кусками задаёт CSS (`margin` у `.author-prefix`
и `.author-sep`), а не разметка: у флекс-элемента свои крайние пробелы схлопываются.

## Гарантия от переполнения

Ступени отвечают за красоту, но не за безопасность: медиазапросы знают ширину экрана и
не знают ширину текста. Она уезжает, если не загрузился Inter (приложение офлайновое),
если у пользователя увеличен шрифт в системе или браузере, если Android WebView применил
свой `fontScale`.

Поэтому в [css/style.css](css/style.css) есть страховочный слой:

- `.author` — `white-space: nowrap` + `overflow: hidden`, **без** `text-overflow: ellipsis`;
- `.author > *` — `flex: none`, то есть не сжимается ничего;
- `.author-name` — единственное исключение: `flex: 0 1 auto` + `min-width: 0` + `overflow: hidden`;
- `.author-link` — `flex-shrink: 0`.

Многоточия нет намеренно: оно съедало как раз звание, ради которого строка и существует
(звание стоит последним, а усекается хвост). Теперь при любом непредвиденном раскладе
уступает только имя, а звание и кнопка остаются целыми.

Проверено на ширинах 240–560px и на стресс-тесте с корневым кеглем 20px и 24px: имя
обрезается, звание показано полностью, кнопка внутри экрана.

## Прочее

- Разделитель — `·` (U+00B7), не дефис.
- Стрелка лежит отдельным `aria-hidden`-спаном, чтобы скринридер не читал «стрелка вправо».
- Для чисел (дистанции, результат), если они вернутся в строку, готов класс `.num` —
  моноширинный шрифт и табличные цифры.
- `id="author-exit"` на ссылке трогать нельзя: за него держится обработчик клика в
  [app.js](js/app.js) и цель Метрики `to_site`.
- В `href` зашиты UTM-метки — по ним на borozdov.ru видно, сколько пришло из калькулятора.
  Подробности в [ANALYTICS.md](ANALYTICS.md).
- Кнопка 26px в высоту, поэтому зону нажатия расширяет `::after` с `inset: -9px` — до 44px,
  не трогая рамку. Это ровно минимум, без запаса: уменьшать кнопку или `inset` нельзя.

## Что проверять при правке текста

Ширины 240 / 280 / 320 / 360 / 375 / 390 / 414 / 480: лейбл и кнопка в одном ряду, лейбл в
одну строку, звание видно целиком, ничего не обрезано, горизонтальной прокрутки нет.

Границы ступеней проверять парами (279/280, 319/320, 409/410, 479/480) — на каждой лейбл
обязан меняться ровно на одну ступень.

Если текст удлиняется, пороги надо пересчитать: замерить ширину варианта и прибавить
«обвязку» — кнопку, зазор подвала и боковые поля `.app` (сейчас 173.8px, от ширины экрана
не зависит).
